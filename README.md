# TG Triage

[![CI](https://github.com/maki072/TGTriage/actions/workflows/ci.yml/badge.svg)](https://github.com/maki072/TGTriage/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Telegram-бот, веб-панель и два режима работы, которые включаются одновременно:

- **Хелпдеск.** Пользователи пишут боту, операторы отвечают в темах супергруппы. Пользователь видит
  только бота и не знает, кто из операторов ему пишет. LLM разбирает обращения и заводит тикеты.
- **Личный триаж Telegram Business.** Сервис читает входящие личные сообщения владельца, отделяет
  задачи от шума и готовит черновики ответов.

Go 1.26, без фреймворков, чистая архитектура (`domain → service → repository/delivery`). Единственная
внешняя зависимость — pure-Go SQLite (WAL), поэтому бинарник статический и без CGO.

## Хелпдеск

Пользователь пишет боту. На первое сообщение бот создаёт в супергруппе тему с именем пользователя и
дальше копирует туда всё, что тот присылает: текст, фото, файлы, голосовые, стикеры, альбомы. Всё, что
оператор пишет в этой теме, бот копирует пользователю в личку от своего имени, без подписи автора.
Ответы на конкретные сообщения сохраняют цепочку в обе стороны, правки сообщений тоже синхронизируются.

В теме:

- сообщение, начинающееся с `//` или `!`, — внутренняя заметка, пользователю не уходит;
- ответ командой `/1` на сообщение пользователя — принудительно создать тикет (сама команда удаляется,
  если у бота есть право удалять сообщения);
- тему можно закрыть и открыть вручную в Telegram или в веб-панели; новое сообщение пользователя
  открывает закрытую тему; удалённая тема создаётся заново.

Сообщения пользователей проходят тот же триаж, что и личные: пачка после паузы уходит в LLM, но с
промптом службы поддержки. Если это обращение, заводится тикет с приоритетом, сутью и черновиком ответа.
Тикет можно создать и вручную: командой `/1`, кнопкой в веб-панели или пересылкой сообщения
пользователя боту (из личного чата с пользователем или из его темы в группе). Карточка тикета
закрепляется в теме пользователя и дублируется в тему «🎫 Тикеты»; кнопки на ней доступны любому
участнику группы.

Дополнительно: приветствие на `/start`, автоответ на новое обращение, отдельный автоответ вне рабочих
часов, напоминание в тему, если пользователь ждёт ответа дольше N минут, уведомление о недоставке
(пользователь заблокировал бота), метка источника из deep-link `t.me/<бот>?start=<метка>`.

### Защита от спама

- **Бан.** Кнопка «🚫 Спам — забанить» под карточкой пользователя в начале его темы, команда `/spam` в
  теме, «Ещё → Спам» на карточке тикета или меню диалога в панели. Сообщения забаненного молча
  игнорируются, тема закрывается, его открытые тикеты закрываются как «не задача». Список забаненных —
  в панели «Диалоги → Спам», оттуда же разбан.
- **Проверка новичков** (настройка «Проверка новых пользователей на спам», включена по умолчанию).
  Сообщение нового пользователя со ссылкой, `@упоминанием`, пересылкой или текстом на китайском,
  японском, корейском, арабском, тайском, иврите, хинди/бенгальском не пересылается в тему, а
  попадает в тему «🛡 Карантин» с кнопками «Пропустить» / «Спам» (то же — в панели). «Пропустить»
  передаёт накопленные сообщения операторам и снимает проверку с пользователя. Латиница и украинский
  не считаются подозрительными. Пользователь считается проверенным, как только ему ответил оператор;
  все, кто писал до включения этой функции, проверенные.
- **Капча** (настройка «Капча для новых пользователей», выключена). Первое сообщение новичка ждёт, пока он
  не нажмёт «Я не бот»; после этого сообщения передаются операторам.
- **Подсказка от AI.** Если триаж помечает сообщение непроверенного пользователя как спам с
  уверенностью от 80%, в его тему приходит предупреждение с кнопкой бана (один раз, автоматически
  никого не банит). Отдельных вызовов LLM для этого нет.

### Настройка группы

1. Создать супергруппу, включить в ней **Темы**. В группе — только операторы и бот.
2. Добавить бота администратором с правами «Управление темами», «Закреплять сообщения» и «Удалять
   сообщения».
3. Бот сам напишет владельцу в личку ID группы с кнопкой «Использовать для хелпдеска» — нажать её,
   бот включит хелпдеск и проверит права. То же можно сделать вручную в веб-панели: ⚙️ Настройки →
   🎧 Хелпдеск → включить, указать ID группы (`-100…`), «Проверить группу».

Оператор — любой участник группы. Операторы открывают ту же веб-панель и видят только хелпдеск:
диалоги, тикеты и историю. Настройки и личные задачи владельца им недоступны.

## Личный триаж (Telegram Business)

Сообщение приходит через Business API, сохраняется в SQLite, и чат ждёт паузу тишины — по умолчанию
20 секунд, но не дольше 120, если пишут без остановки. Накопленная пачка уходит воркеру: тот собирает
контекст (последние сообщения диалога + открытые задачи с этим собеседником) и вызывает LLM — Claude,
Gemini, Groq, Mistral или OpenRouter, по очереди из списка ключей, — требуя строгий JSON: тип сообщения,
уверенность, заголовок, приоритет, дедлайн, стратегия ответа.

Если уверенность ниже порога чувствительности или сообщение явно не задача — оно просто попадает в
журнал, без карточки. Продолжение уже открытой задачи дополняет её, а не дублирует. Однозначный шум
(«спасибо», «ок», эмодзи) отсеивается ещё до LLM.

Задачу можно завести и вручную, переслав боту сообщение из любого чата. Управление — кнопками под
карточкой или в веб-панели.

Подключение: бот у [@BotFather](https://t.me/BotFather) с включённым **Business Mode**, затем
**Настройки → Telegram Business → Чат-боты** → выбрать бота и выдать права «Отвечать на сообщения» и
«Читать сообщения». Нужен Telegram Premium.

## Провайдеры

Claude и Gemini — через нативные API; Groq, Mistral и OpenRouter — общий OpenAI-совместимый адаптер.
Ключи собираются в цепочку: вызов идёт сверху вниз, и если ключ упёрся в квоту, отклонён или
провайдер недоступен из региона, сразу пробуется следующий. Кнопка «🧪 Проверить» тестирует каждый
ключ отдельно.

## Конфигурация

В `.env` остаются только bootstrap-переменные: `TELEGRAM_BOT_TOKEN`, `OWNER_ID`, `WEBAPP_ADDR`,
`SOCKS5_PROXY`, `DB_PATH` и логирование — см. [`.env.example`](.env.example). Токен и владелец нужны до
открытия базы: ими подписывается вход в веб-панель.

Всё остальное хранится в базе и меняется в веб-панели без перезапуска: ключи и модели AI, триаж,
хелпдеск, рабочие часы, бэкапы, часовой пояс, публичный адрес панели. Исключение — число параллельных
анализов, оно применяется после перезапуска (кнопка есть в панели). Переменные прежних версий
импортируются в базу при старте один раз, после этого их можно удалить из `.env`.

## Бэкапы

Раз в сутки в заданное время сервис делает `VACUUM INTO` — согласованную копию базы без остановки —,
сжимает её в `backups/tgtriage-YYYYMMDD-HHMMSS.db.gz` рядом с базой, хранит последние N файлов и
отправляет каждый владельцу в личку с ботом. Бэкап можно сделать и вручную из настроек.
Восстановление: остановить сервис, распаковать файл поверх `tgtriage.db`, удалить `-wal`/`-shm`,
запустить.

## Почему SQLite

Нагрузка хелпдеска — сотни, от силы тысячи сообщений в день; SQLite в режиме WAL спокойно выдерживает
тысячи записей в секунду. Все запросы идут через одно соединение, поэтому `database is locked` не
возникает. Вызовы LLM и Telegram выполняются вне транзакций и базу не блокируют. WAL с
`synchronous=NORMAL` при сбое питания может потерять последние транзакции, но не повреждает файл;
от остального защищают ежедневные бэкапы. Упираться SQLite начнёт при нескольких инстансах сервиса
на одну базу, а этот бот — один процесс на токен.

## Сборка

```bash
make test        # go test -race
make build-linux # статический bin/tg-triage-linux-amd64
```

Локально: `cp .env.example .env`, заполнить значения, `make run`.

## Деплой на Debian

```bash
sudo ./deploy/install.sh bin/tg-triage-linux-amd64
sudo nano /etc/tg-triage/tg-triage.env
sudo systemctl restart tg-triage
```

Создаёт системного пользователя, каталоги и systemd-юнит с hardening (`ProtectSystem=strict`,
изолированный `/var/lib/tg-triage` и т.д.). Логи: `journalctl -u tg-triage -f`. Кнопка «Перезапустить»
в панели завершает процесс с ненулевым кодом, и systemd поднимает его снова.

Готовые сборки под тег `vX.Y.Z` собирает GitHub Actions — статический бинарник и инсталлятор-архив
лежат в [Releases](../../releases).

## Ограничения

- Удаления сообщений Bot API не присылает ни для лички, ни для групп — удалённое сообщение остаётся
  у второй стороны. Правки текста и подписей синхронизируются, замена медиа — нет.
- Голосовые, фото и файлы модель видит только как подпись с типом — содержимое не распознаётся.
- Пересланное из темы сообщение сопоставляется с пользователем по времени и тексту; если не вышло,
  используйте `/1`.
- В Business-чатах Bot API не даёт ставить реакции — «В работу» вместо этого отмечает сообщение
  прочитанным.
- Текст переписки уходит выбранному LLM-провайдеру; история хранится заданное число дней, задачи —
  бессрочно.
- Один инстанс на токен бота: long polling, вебхук снимается при старте.
